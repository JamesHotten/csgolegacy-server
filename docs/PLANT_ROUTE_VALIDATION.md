# Legacy 下包点、集合与回防

旧版 Inferno B 的包匪订单落到 `425.0 2787.5 160.0`，引擎的 `m_bInBombZone` 为假。它在包点包围盒内，但位于实际下包触发体以外；十图旧版 20 个默认目标中仅这一处复现该问题。

最终版包区检查为 20/20：Inferno、Train、Mirage、Nuke、Dust II、Overpass、Vertigo、Cache、Ancient、Anubis 的 A/B 目标均通过引擎判定。Anubis 的低矮触发体需要检查玩家体积与触发体的重叠，仅靠中心线探测会漏判。

`sm_bot_t_safe_plant 1` 会校验旧目标的站立空间及实际包区；需要时选择附近可达的 NAV 位置，优先选择包区内部、而非仅在边缘与包区重叠的位置。普通、转点以及紧急下包共用目标校验。包匪未进区时按 8 单位接近，进区后交还原生 BOT；没有安全点时也交还原生 BOT。不会设置包区属性、按键下包或伪造游戏事件。

`sm_bot_t_route_timing 1` 仅作用于 Mirage 和 Nuke 的命名入口集合。非 Rush 方案在持包 BOT 持续前进时，最多多给 5 秒到位；接敌与原有到位门槛仍能提前推进。没有进展时沿用原有超时，进度统计按三维距离。

`sm_bot_ct_clear_site_defuse 1` 只在下包且没有存活 T 时交还原生拆包 AI，不让清场后的 CT 继续等外围集合；有敌人的回防规则不变。以上三个开关都可分别设为 0 回退。

## 验收工具

`tests/plant_route_runtime_probe.sp` 只在空的本机测试服开启。包区模式将测试 BOT 放到发布的目标，读取引擎实际包区判定；实跑模式让 T 从出生点跑位和实际下包，然后移除测试对手，CT 从出生点实际回防、拆包。后者不生成或注入任何下包／拆包事件，不衡量实战交火胜率。

独立 128 tick 服实跑（CT 在下包前留在出生区，清场后释放，测试 CT 有拆弹器）：

| 场景 | 从冻结结束到真实下包 | 从下包到真实拆除 |
| --- | ---: | ---: |
| Inferno B（最终版复测） | 28.89 秒 | 18.35 秒 |
| Mirage A（A 坡／宫殿） | 32.61 秒 | 12.35 秒 |
| Nuke B（Ramp／Secret） | 36.77 秒 | 28.85 秒 |

Nuke 的这轮集合仍在上限后推进；日志确认包匪从上层经通道到达下层，而非误判上下层已经到位。Mirage 队伍也按实际到位与时限推进。计时是这些测试样本，不是性能保证。

Inferno 复测曾遇到喷泉附近可下包但原生 BOT 无法及时接近炸弹进行拆除的位置；改用内部优先后，包匪向 `475 2650 160` 推进，CT 从出生点完成回防和拆弹。Mirage 与 Nuke 的已测路线未涉及该候选位置的优先顺序调整。

正式服停机更新了 CT/T 调度器和 BetterBots 连接层的三个插件及对应源码。更新前后比对的 235 项配置、SQLite 与其他插件文件哈希一致。回滚目录位于正式服 SourceMod 的 `data/plant-and-retake-rollback-20261114`；停服后可按原相对路径恢复六个文件。测试插件不部署到正式服。
